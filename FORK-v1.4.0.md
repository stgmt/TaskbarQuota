# Форк-релиз v1.4.0 — все лимиты из ОМП в виджете

База: `zioder/TaskbarQuota` v1.3.2. Новая версия: **1.4.0** (минорная — новый источник данных, без ломки старого).

## Что должно быть видно после установки

Виджет по умолчанию — плавающее окно на столе. По клику раскрывается список
всех сервисов, подключенных к ОМП, каждый — красивой полосой: сколько
потрачено, сколько осталось, когда сброс. Цветом подсвечиваем состояние:
норма, предупреждение, исчерпан.

## Полный список лимитов ОМП на этот релиз

Снято командой `omp usage --json` 07.09.2026. Всего 6 записей, 5 сервисов,
18 строк лимитов. Все 18 обязаны показаться в раскрытом окне.

- opencode-go, аккаунт 1: окно 5 часов — 0%, окно неделя — 0%, окно месяц — 100% (исчерпан)
- opencode-go, аккаунт 2: окно 5 часов — 0%, окно неделя — 0%, окно месяц — 100% (исчерпан)
- zai: кредиты 5 часов — 132 из 2000 (6,6%), кредиты неделя — 5236 из 10000 (52,4%)
- xai-oauth: кредиты неделя — 0 из 100 (0%)
- google-antigravity: Google неделя — 93,3% (предупреждение), Anthropic неделя — 71,1%, OpenAI неделя — 71,1%, Google 5 часов — 46,9%, Anthropic 5 часов — 0%, OpenAI 5 часов — 0%
- cline-pass: 5 часов — 0%, 7 дней — 0%, 30 дней — 11%

Правила показа: проценты — как есть из ОМП, кредиты — «потрачено из лимита»
плюс остаток, время сброса — местное время, пустой сброс (как у cline-pass
5ч/7д) — без строки времени, только полоса. Аккаунт, у которого все месячные
окна съедены на 100%, прячется целиком; то же — когда съедены все недельные
окна. Прячем на каждый опрос заново, ничего не удаляем: после сброса строки
возвращаются сами. Если съедены вообще все — показываем
как есть, чтобы не было пустого окна. Одинаковые названия различаем меткой
в скобках («Google», «Anthropic»), несколько аккаунтов одного сервиса —
номером («#1», «#2») или началом почты.

## Что меняется в коде

1. Новый источник «ОМП»: файл `src/TaskbarQuota.App/Usage/Providers/OmpProvider.cs`.
   Читает вывод `omp usage --json` (потом — общий файл-кэш), отдает его
   строками в общий список. Регистрация рядом с остальными в
   `UsageCoordinator.cs`. Отдельных входов не надо — ОМП уже вошел везде сам.
2. Окно на столе по умолчанию: `FloatingUsageWindow.xaml(.cs)` — стартовый
   режим, положение и прозрачность помнятся. Клик без перетаскивания открывает
   `FlyoutWindow.xaml(.cs)` со всеми 18 строками, клик мимо — закрывает.
3. Только x64: убрать ARM64 из `TaskbarQuota.App.csproj`
   (`Platforms`, `RuntimeIdentifiers`), из `.github/workflows/release.yml`
   (матрица сборки, текст про выбор процессора) и оставить один установщик
   `TaskbarQuotaSetup-1.4.0-x64.exe` в `installer/TaskbarQuota.iss`.
4. Версия 1.4.0: `Version`, `AssemblyVersion`, `FileVersion` в csproj.
5. Тег `v1.4.0` → сборка запускается сама, установщик прикладывается к релизу
   на Гитхабе вместе с текстом из раздела «Что должно быть видно».

## Порядок работ

1. OmpProvider + регистрация, проверка: все 18 строк из раздела выше видны.
2. Стартовый режим — окно на столе, клик раскрывает всех, клик мимо закрывает.
3. Выпиливание ARM64 везде (проект, сборка, установщик), проверка: один x64-файл.
4. Версия 1.4.0, пробная сборка, скриншоты окна и раскрытого списка.
5. Тег v1.4.0, релиз на Гитхабе с установщиком и этим текстом.

## Готово — когда

- На чистом столе окно висит, цифры совпадают с `omp usage` один в один.
- Клик показывает все 18 строк красиво: полоса, остаток, время сброса.
- Второй процессор нигде не собирается, в релизе один x64-установщик.
- Магазин приложений не трогаем, только Гитхаб.

## Мета из WSL

Новый сервис «Meta»: читает локальные записи сессий muse из WSL
Ubuntu-24.04 и показывает потраченные токены за 5 часов и 7 дней. Серверная квота есть: 5-часовое и недельное окна в процентах со временем
сброса, обновляются раз в минуту вместе с остальными. Если сервер недоступен —
показываем локальные счётчики токенов, чтобы карточка не была пустой.
Закреплён по умолчанию.
